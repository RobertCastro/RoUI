Toast

experimental

Notificación flotante y transitoria que anuncia un evento sin robar el foco del usuario.

Cuándo usarlo

  • Confirmar el resultado de una acción que el usuario acaba de disparar (guardar, enviar, copiar).
  • Anunciar un evento asíncrono breve que no requiere que el usuario decida nada.

Cuándo no

  • Para un mensaje persistente ligado a una sección de la página: usa Alert.
  • Para un anuncio global de producto que no desaparece solo: usa Banner.
  • Para pedir una decisión o dato antes de continuar: usa Modal.

Anatomía

<div class="ro-toast-region"></div>
  • El marcado solo aporta la región de posicionamiento: el toast-controller la crea si no existe y le inserta cada toast como su propia región viva.
  • Cada toast lleva role=status (éxito/info, anuncio cortés) o role=alert (error, anuncio asertivo); el controlador lo asigna según la variante.
  • El icono es decorativo (aria-hidden); el mensaje de texto es el único contenido anunciado.
  • El botón de cierre lo genera el controlador con aria-label ("Cerrar" por defecto).

API

Primitiva

import { createToastController } from "@robertcastro/roui/primitives/toast-controller";

Teclado y accesibilidad

TeclaAcción
TabAlcanza el botón de cierre del toast visible.
Enter / EspacioDescarta el toast enfocado.

Contrato de accesibilidad: toast

  • El foco nunca se mueve al toast: el usuario sigue en su tarea y el lector de pantalla lo anuncia al insertarse.
  • El cierre automático (5000 ms por defecto) se pausa al enfocar o pasar el puntero por el toast, y se reanuda al salir.
  • duration: 0 (o Infinity) deja el toast persistente hasta que el usuario lo cierre manualmente.
  • role=alert se reserva para errores: interrumpe al lector de pantalla. Éxito e info usan role=status.

Ejemplos

Disparo desde botones de acción

Do / Don't

Sí

  • Usa el toast para confirmar una acción que el usuario ya realizó.
  • Mantén el mensaje corto y accionable si hace falta un siguiente paso.
  • Deja que el usuario pause el cierre automático al enfocar o pasar el puntero.

No

  • No uses un toast para pedir una decisión: no atrapa el foco ni ofrece botones de confirmación.
  • No apiles toasts indefinidamente sin límite ni control de tiempo.
  • No repitas en el toast un error que ya se muestra inline junto al campo.

Madurez

experimental Apariencia o API sin garantías completas; puede cambiar sin aviso.
