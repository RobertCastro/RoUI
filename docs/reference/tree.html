Seleccion y navegacion

Tree view

experimental

Lista jerárquica plegable de nodos padre/hijo (p. ej. curso › semana › módulo), con un nodo activo resaltado.

Cuándo usarlo

  • Estructuras anidadas de 2-3 niveles donde el usuario necesita ver y plegar ramas (temario de un curso, árbol de archivos).
  • Cuando Sidebar con grupos planos ya no alcanza para representar la jerarquía.

Cuándo no

  • Cuando necesitas navegación por teclado tipo WAI-ARIA treeview (flechas para expandir/colapsar y moverte entre nodos, Home/End): esa primitiva todavía no existe en RoUI — ver notas de accesibilidad.
  • Para listas planas sin jerarquía real: usa List group.
  • Para una jerarquía de solo 2 tramos (sección › página actual): un Breadcrumb es más simple.

Anatomía

<ul class="ro-tree">
  <li class="ro-tree__item is-open">
    <div class="ro-tree__row"><svg class="ro-icon ro-icon--sm ro-tree__chevron" aria-hidden="true"><use href="#ro-i-chevron-right"></use></svg> Semana 1</div>
    <ul class="ro-tree__children">
      <li class="ro-tree__item"><div class="ro-tree__row ro-tree__row--leaf ro-tree__row--active">Estado actual de AI</div></li>
      <li class="ro-tree__item"><div class="ro-tree__row ro-tree__row--leaf">Input &gt; Proceso &gt; Output</div></li>
    </ul>
  </li>
</ul>
  • La estructura usa <ul>/<li> anidados: el número de hijos y la profundidad se anuncian correctamente aunque no haya rol tree explícito.
  • Cada fila (ro-tree__row) es hoy un <div> con un manejador de clic que alterna la clase is-open del <li> padre; no es un <button> y no tiene tabindex propio (ver a11y.notes).
  • Los nodos hoja llevan ro-tree__row--leaf para alinearse sin chevron; el nodo activo se marca con ro-tree__row--active.

API

Clases

ClaseDescripción
.ro-treeLista raíz del árbol.
.ro-tree__itemNodo (rama u hoja).
.ro-tree__rowFila clicable de un nodo.
.ro-tree__row--leafFila de nodo hoja (sin hijos ni chevron).
.ro-tree__row--activeFila del nodo actualmente seleccionado.
.ro-tree__chevronIcono indicador de expandido/colapsado.
.ro-tree__childrenLista anidada de hijos de una rama.

Tokens que consume

--ro-text-sm --ro-radius-lg --ro-ink-70 --ro-ink-04 --ro-secondary-soft --ro-ease

Sin JavaScript: es CSS sobre HTML nativo.

Teclado y accesibilidad

TeclaAcción
Tab / Shift+TabNo aplica hoy: las filas no son enfocables por teclado (son <div>, no controles nativos).
ClicÚnico mecanismo actual para expandir/colapsar una rama o seleccionar un nodo.

Contrato de accesibilidad: content-and-status

  • Estado actual, tal cual: este componente todavía no implementa el patrón WAI-ARIA treeview (role=tree, role=treeitem, aria-expanded, aria-selected, flechas de teclado). Queda documentado como pendiente de una primitiva dedicada, igual que Segmented.
  • Hoy las filas solo responden a clic del mouse: no son alcanzables ni operables por teclado. Si la navegación por teclado es un requisito duro, no adoptes Tree todavía; usa Sidebar (items son <a> nativos) o un menú de disclosure.
  • Cuando exista el controlador dedicado, cada ro-tree__row debería ser un elemento enfocable (rol treeitem) con aria-expanded en las ramas y aria-selected en el nodo activo.

Do / Don't

Sí

  • Usa <ul>/<li> anidados para conservar la semántica de lista aunque falte el rol tree completo.
  • Limita la profundidad a 2-3 niveles: más allá, la lectura y el plegado se vuelven difíciles de seguir.
  • Documenta en tu producto que la navegación es solo por mouse/touch mientras no exista el controlador dedicado.

No

  • No presentes Tree como accesible por teclado: hoy no lo es.
  • No uses Tree para una lista sin jerarquía real: es más costoso de construir y de usar que List group.
  • No inventes atributos aria-expanded/aria-selected en el marcado sin implementar también el comportamiento de teclado que esos atributos prometen.

Madurez

experimental Apariencia o API sin garantías completas; puede cambiar sin aviso.
