Banner

experimental

Franja de anuncio persistente en la parte superior de la página, visible hasta que el usuario la cierra.

Cuándo usarlo

  • Anunciar un cambio de producto, promoción o aviso relevante para toda la sesión.
  • Comunicar un mensaje que debe permanecer visible mientras el usuario navega, no solo un instante.

Cuándo no

  • Para confirmar el resultado de una acción puntual: usa Toast (desaparece solo).
  • Para un aviso contextual ligado a una sección o formulario: usa Alert.

Anatomía

<div class="ro-banner">🎉 Nuevo: RoUI 1.0 ya disponible. <a href="#">Ver novedades</a><button class="ro-banner__close" aria-label="Cerrar aviso"><svg class="ro-icon ro-icon--xs" aria-hidden="true"><use href="#ro-i-x"></use></svg></button></div>
  • No tiene primitiva JS propia: el marcado es estático y el consumidor decide cómo ocultar el banner al cerrarlo (por ejemplo removiendo el nodo o con display:none).
  • El enlace dentro del banner hereda color y usa subrayado para no depender solo del contraste de fondo.
  • El botón de cierre necesita nombre accesible (aria-label) y va al final con margin-left:auto.

API

Clases

ClaseDescripción
.ro-bannerContenedor base (fondo oscuro por defecto).
.ro-banner--primaryVariante con fondo primario.
.ro-banner--brandVariante con fondo de marca (secondary).
.ro-banner--softVariante tenue sobre fondo claro.
.ro-banner__closeBotón de cierre.

Tokens que consume

--ro-ink --ro-on-dark --ro-primary --ro-secondary --ro-ink-04 --ro-space-3

Sin JavaScript: es CSS sobre HTML nativo.

Teclado y accesibilidad

TeclaAcción
TabAlcanza el enlace y el botón de cierre, en orden.
Enter / EspacioActiva el enlace o cierra el banner desde el botón enfocado.

Contrato de accesibilidad: toast

  • A diferencia de Toast, el banner es persistente: no se cierra solo ni tiene temporizador; permanece hasta que el usuario pulsa el botón de cierre.
  • No usa role=status ni role=alert porque no es un anuncio dinámico transitorio; es contenido visible desde la carga de la página.
  • Si el banner se inserta dinámicamente después de la carga (por ejemplo tras una acción del usuario), considera aria-live=polite en su contenedor para que se anuncie.

Do / Don't

Sí

  • Reserva el banner para un solo mensaje global a la vez.
  • Ofrece siempre una forma de cerrarlo si no es crítico para completar la tarea.
  • Usa un enlace real (no un botón que simula navegación) para "Ver novedades".

No

  • No lo uses para mensajes que deben desaparecer solos: eso es Toast.
  • No apiles más de un banner a la vez en la misma página.
  • No pongas ahí una decisión bloqueante: eso es Modal.

Madurez

experimental Apariencia o API sin garantías completas; puede cambiar sin aviso.
