Fundamentos visuales

Prose

experimental

Estiliza contenido HTML renderizado desde markdown (artículos, lecciones) con tipografía, listas, citas y código coherentes.

Cuándo usarlo

  • Renderizar contenido generado desde markdown: artículos, lecciones, descripciones largas.
  • Cuando el HTML interno lo produce un parser externo y no controlas cada clase, solo el contenedor.

Cuándo no

  • Para titulares o texto de UI puntual controlado a mano: usa las clases de Typography (ro-display, ro-h2, ro-body) directamente.
  • Para un único fragmento de código aislado fuera de un artículo: usa Code (ro-code / ro-codeblock) en vez de envolverlo en ro-prose.

Anatomía

<div class="ro-prose">
  <h2>El Arte del "Technical Brief"</h2>
  <p>La calidad del código generado por IA depende del <strong>contexto</strong> que le das. Un brief claro define requerimientos, restricciones y <a href="#">Definition of Done</a>.</p>
  <ul>
    <li>Contexto del problema</li>
    <li>Requerimientos y restricciones</li>
    <li>Criterio de aceptación</li>
  </ul>
  <blockquote>Contexto de calidad = código de calidad.</blockquote>
  <p>Usa <code>npm run build</code> para generar el bundle:</p>
  <pre><code>npm install
npm run build</code></pre>
</div>
  • ro-prose es un contenedor de contexto: todos los estilos se aplican a elementos HTML nativos (h1–h4, p, ul, ol, blockquote, code, pre, a, img, hr) dentro de él, no a clases ro-* adicionales.
  • El espaciado vertical entre bloques lo da el selector > * + *: no agregues margin manual a los hijos directos.
  • code y pre dentro de ro-prose ya heredan el estilo de código sin necesitar las clases ro-code / ro-codeblock.

Tokens que consume

--ro-text-sm --ro-ink-72 --ro-font-display --ro-ink --ro-text-3xl --ro-text-2xl --ro-text-xl --ro-text-lg --ro-tracking-tight --ro-weight-bold --ro-secondary --ro-ink-40 --ro-ink-70 --ro-font-mono --ro-ink-05 --ro-radius-sm --ro-radius-xl --ro-ink-10 --ro-radius-lg

Sin JavaScript: es CSS sobre HTML nativo.

Teclado y accesibilidad

Contrato de accesibilidad: content-and-status

  • Respeta una jerarquía de encabezados sin saltos dentro del contenido fuente (h1→h2→h3→h4); ro-prose no corrige saltos, solo da estilo al nivel que reciba.
  • Los bloques de código dentro de prose ya usan <pre><code>, preservando espacios y permitiendo navegación por teclado del lector de pantalla.
  • Las imágenes dentro de prose necesitan alt descriptivo en el markdown de origen: el estilo de ro-prose img no aporta accesibilidad, solo max-width y radio.

Do / Don't

Sí

  • Deja que el markdown de origen defina la jerarquía de encabezados; ro-prose solo la estiliza.
  • Envuelve el contenido renderizado completo en un único ro-prose, no fragmento por fragmento.
  • Usa ro-prose para contenido largo y mixto (texto + listas + código), no para un solo párrafo suelto.

No

  • No apliques ro-code o ro-codeblock a los <code>/<pre> internos de ro-prose: ya están estilizados, y duplicar clases genera inconsistencias.
  • No metas componentes interactivos complejos (modales, tablas de datos) dentro de ro-prose: está pensado para contenido de lectura, no UI de aplicación.
  • No fuerces un h1 adicional dentro de ro-prose si la página ya tiene su propio h1 fuera del contenedor: rompe la jerarquía de la página.
